## F1 — Independence is relative to the list; with an empty list everything is independent; the model hardcodes the person

Location: `gravity/docs/findings.md` row F1; `gravity/evidence/Dmp/Layer.lean` (`empty_list_makes_everything_independent`, line 89; `DoT.minted`, line 105).

**Restated.** DMP defines independence as sharing no member of the failure classes "declared for their layer in the minting record … (host, key, author, engine, operating image, person, time source, and whatever else the minting lists). Independence is always relative to that list; the list is configuration (T4)" (01-constitution.md, the words, lines 34–36). On that definition alone, an empty declared list makes any two witnesses independent — including the same witness twice. The model repairs this by defining `DoT.minted fcl := independent (person :: fcl)` (Layer.lean:105), i.e. the person is always a declared class and is not configuration. DMP's text never says the person is always declared.

**For it being a real hole.** A literal implementation of the words diverges from the model on exactly the case that matters most. The corpus itself demands a second, independent implementation written from the specification only (chapter 06, class IIb: "Differential testing: the rules run against a second, independent implementation written from the specification only"). A spec-faithful differential implementation would accept a pressed pair under an empty list where the model refuses it — and the whole point of G0/T-P is that a pressed pair must never be minted. G0 speaks of pressed instances only through persons ("Both of its witnesses trace to one person", line 134), and T-P/R2Stable derive the collapse from that, but the *definitional* tie — that the person's membership in the list is non-optional — exists in the model, not in the words. T4 ("the failure classes … is fixed by both halves at the minting", lines 248–249) actively invites reading the person as droppable configuration. The gap is in the load-bearing definition, not an edge note.

**Against.** The behaviour the text wants is enforced without the definitional fix: G0 defines a pressed instance and marks it ("it is marked as pressed in every artefact it issues, and nothing it does is fully trusted by a minted instance"), and T-P's verdict sentence ("Gravity's verdict on a pressed instance is therefore 'out of spec'", line 593) plus "Never axiomatically sound; Gravity abhors it" already forbid minting it. The word "person" already appears in the words' example list (line 35), so a careful reader sees it is an expected class. The model's `person :: list` is a *strengthening*, so no theorem proven on the model over-claims relative to the text; the exposure is only to a re-implementer who reads the definition in isolation. Minting is a human ceremony (G0: "done by people the owner already trusts, outside CMOS"), which is a second, non-formal guard.

**Verdict.** Real hole — the definition as written is weaker than what every proof assumes, and the corpus's own differential-testing rule is the concrete way that gap becomes live. Confidence 75%. Severity: low (the unsafe reading is caught by T-P's verdict and by the human minting; the fix is one sentence). Why it matters: it is the one place where "follow the text exactly" and "follow the model exactly" disagree on minting a pressed pair. Suggested fix: adopt the candidate wording in the words: "…and whatever else the minting lists; the person is always among them." [argued throughout; quotes from 01-constitution.md lines 34–36, 133–135, 593; Layer.lean lines 88–105]

## F2 — The expected field is precomputable; the settled layout is an equilibrium, not an optimum; no canonical equilibrium or tie-break in DMP

Location: `gravity/docs/findings.md` row F2; `gravity/evidence/Dmp/R2Stable.lean` (`st_settles` line 159, `st_equilibrium_not_optimal` line 188); `gravity/evidence/Dmp/Theory.lean` §7 (`Recipe.digest_congr`, lines 266–293); DMP T33 (constitution lines 559–567).

**Restated.** The digest (depth, mass per line) is a function of the recipe alone [argued; Theory.digest_congr, and Cmb.lean's kernel-checked examples `layoutF.digest = [(0,5),(1,2),(1,2),(2,1),(2,1)]` := rfl, Cmb.lean:223]. But Lensing's accepted reorganisations only strictly lower the potential and terminate (`st_settles`); the kernel-checked three-state example (potentials 1, 2, 0; `st_equilibrium_not_optimal`, "by decide") shows a reachable equilibrium that is not the minimum. DMP never asks for a canonical equilibrium or a tie-break between equal-potential layouts.

**For.** The owner's plan ("precompute the perfect deployment") reads as if the deployment has one perfect target state. The model says: only the *expected field* is recipe-determined; the settled placement depends on start state and loss history, and can sit above the minimum, and two histories can settle differently. T33's text — "Two CMOS instances deployed from the same recipe span the same VIBE field, up to identity" (line 561) — covers the expected field, not the settled layout. Concretely exposed: any verifier or runbook that compares a *measured* live field against the *precomputed* digest as a pass/fail gate will flag healthy systems (equilibrium above the minimum) or, worse, accept drift because "the field matches" while the settled placement differs between instances. Nothing in DMP says which of two equal-potential layouts is "the" deployment, so the "perfect deployment" is underdetermined by the text.

**Against.** No DMP theorem is weakened: T33 claims isomorphism of fields of instances "deployed from the same recipe", and in the simulator "on one injected clock the two fields are equal" — the model agrees. Equilibrium-not-optimum is the standard property of potential games (R2Stable.lean's own prior art: Monderer and Shapley), and nothing in the text ever promises a global optimum; "settles, never oscillates" is all K4/Lensing claim. The finding's own candidate defers the decision ("Decide later whether the recipe carries a tie-break rule … or whether 'the perfect deployment' means the Φ=0 target"), which signals this is a design choice for the owner, not a contradiction. The digest's role in T33 is publication "next to its proof-run hash" — an expected field, and the text never says the live field must equal it.

**Verdict.** Real hole — a silence that will mislead the precompute/perfect-deployment workstream specifically, since the one sentence the owner uses for it ("the perfect deployment") is exactly the phrase nothing in the text licenses. Confidence 70%. Severity: medium (misled verification semantics for deployment and drift monitoring; no safety theorem breaks). Why it matters: it decides whether a live-field mismatch means "broken" or only "warm". Suggested fix: as the row says — prove the precomputable half, then have the owner pick: tie-break rule in the recipe for a canonical equilibrium, or define "perfect deployment" as the Φ=0 target with temperature as distance from it. [argued; quotes from constitution line 561, T33; R2Stable.lean lines 153–188]

## F3 — Two kernels, one exporter: the shared cause DMP never names

Location: `gravity/docs/findings.md` row F3; `gravity/.github/workflows/lean-evidence.yml` lines 44–71; DMP G0 assumption-register list (constitution lines 142–143); SETUP.md gaps E1/G1 (grep, lines 53, 77).

Additionally, both `lean4export` and `nanoda_lib` are cloned at their default branch, unpinned (workflow lines 54, 60; SETUP.md gap G1 already flags it).

**For.** This is precisely T29's scenario inside the evidence chain: the two "witnesses" for "this theorem is checked" are Lean's kernel and nanoda, and an undeclared common component stands between their inputs. A lean4export mistranslation that stays type-correct under nanoda (the workflow itself notes the Nat/String kernel extensions must be enabled on the nanoda side "because Lean's own kernel has them" — semantic surface shared by construction) would have nanoda verifying a different proposition than Lean checked, and the pipeline would report double acceptance. And the register the text points at does not yet exist as a section: `06-black-hole.md` (read in full) holds The parts, Supernova classes and GRB runs, no assumption register; the register exists only as a pointer list in G0 (constitution lines 142–143: "the provers' logic, the shared machines" — generic, exporter unnamed). **Against.** The exporter sits on the *corroboration* path, not the primary one: Lean's kernel already checked the theorems before any export, and its acceptance is unweakened. The class is arguably already declared: G0's register names "the provers' logic" wholesale, and lean4export is Lean FRO's own tool (same author as Lean — an "author/engine" class member under the words' example list), so a minting record declaring "provers' logic incl. exporter" covers it. The workflow exports only the theorems and their dependencies, requires a clean nanoda line (line 70), and SETUP.md tracks the unpinned clones as named gap G1 — the corpus is not hiding this, it has not fixed it yet.

**Verdict.** Real hole — the second-witness guarantee of the evidence chain is currently "two kernels and one exporter", and DMP's declared-cause mechanism (minting record / assumption register) nowhere records the exporter, which is exactly what T29 requires for a shared cause to be honestly handled. Confidence 80%. Severity: medium (no theorem becomes false; the independence claim — the point of the two-kernel setup — is overstated until fixed). Why it matters: every "checked by two independent kernels" statement is weaker than it reads. Suggested fix: a second exporter, or nanoda reading the compiled `.olean` itself, so the kernels share no step; close gap G1 (pin both clones by commit) in the same stroke. [argued; quotes from workflow lines 44–48, 63–70; constitution lines 398–404 (T29), 142–143, 963; SETUP.md G1]

**Verdict.** Real hole, at the "hole in the assurance story" level rather than the "false statement" level: the corpus's central quantity (independence) rests on an artefact DMP itself admits no chain reaches, with no named second witness, in a system whose whole method is two witnesses for everything. Confidence 65%. Severity: medium (an under-declared list silently degrades every independence guarantee while every proof remains "valid"). Why it matters: it is the difference between "two witnesses" and "two witnesses, probably". Suggested fix: as the row says — an independent audit of shared dependencies, Blazar style, signed as a record beside the list at every minting and re-minting. [argued; quotes from constitution lines 127, 138–143, 398–404]
